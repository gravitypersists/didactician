How Didactician Teaches

Being an Account of a Machine that Plans Its Pages as Lessons

❧

For Claude Code users who know skills and subagents (intermediate; new to learning science) · about 7–8 minutes · scrollytelling in two halves + short article segments

Shape: A sticky pipeline canvas (Plate I) walks through the 8 stages, each with its real artifact, then returns in a "why" mode that overlays four design rules. The second half is an article: cognitive load with one contrasting pair of figures, then a step-through that maps this page's own plan entry onto the section the reader just read. A process suits a step-locked canvas; cognitive load is a set of distinctions, which suits predictions and contrasts better. Rejected: one long scrolly for everything (cognitive load would become something to watch, not predict).

Objectives:

  • o-1 Explain the pipeline at a high level and recognise each stage's artifact. checks: none — the canvas keeps it all visible and returns twice; a stage-name quiz would test vocabulary
  • o-2 Explain why it's shaped this way: the orchestrator never authors; files, not chat; scripts gate the checkable, agents judge the rest; you approve the plan first. checks: k-01
  • o-3 Explain cognitive load (limited working memory; intrinsic vs. extraneous) and predict how a design choice moves it. checks: k-02
  • o-4 Explain how the designer turns that into page decisions: objectives as what the reader can do, scope in ideas plus a cut list, checks and widgets chosen for learning. checks: k-04 (and Plate IV)

check_plan warnings: see the checkpoint summary (expected: 4 objectives for an 8-min piece, above the ≤ 3 guide; kept because the brief fixes them and each is served by one or two segments).

§ 2s-02

The pipeline, one stage at a time

whole first → step-through · B1o-1

The whole pipeline as one picture, then each stage opened with the file it produces.

Step 0 (draft): "Eight stages. Each one hands the next a file, never a chat message."

  • 1 Intake: the orchestrator turns your one-line request into brief.md: audience, time, objectives. It asks you only what it can't infer.
  • 2 Research: question-driven and capped. Each claim is tied to an objective, and anything off-topic goes to a parking lot.
  • 3 Plan: the instructional designer writes a learning plan, a wireframe mockup and a cut list (§ 5 opens this one).
  • 4 You approve: always. Approve, revise or rescope before anything is built.
  • 5 Build: a page builder, plus one widget builder per complex widget, in parallel.
  • 6 Gate: a Playwright script renders the page at 360, 768 and 1280px and fails it on overflow, broken arrows, console errors…
  • 7 Review: an accuracy reviewer and a pedagogy/UX reviewer, each in a fresh context.
  • 8 Deliver: a site/ folder for any static host, plus a log.md of everything that happened.

§ 3s-03

Why it's built this way

predict → 4 overlays · B1o-2

Each structural choice prevents a failure the reader knows from their own agent work. Confront "self-review is enough".

Problem 1 · Predict · k-01
The page builder has finished the page. Before it ships, which check would you trust most to catch a claim it got subtly wrong?
  1. A) Ask the builder to re-read its page and double-check its claims. (tempting)
  2. B) A fresh reviewer that sees only the brief, the fact base and the page, not the builder's reasoning.
  3. C) The Playwright gate: if it passes, the page is fine.
Solution. B. The builder knows what it meant and reads that intent back into the text; LLM judges have been found to rate their own outputs higher than human annotators do (GPT-4, Llama 2). C checks only what a machine can check. Didactician runs C, then B. Whether that split beats one agent reviewing itself hasn't been measured; the skill's own notes list it as a hypothesis to test.
  • W1 The orchestrator never authors. Your main session only dispatches, so no reviewer is grading its own work, and raw research stays out of the context that writes the prose.
  • W2 Everything is a file. Every handoff prompt and report is saved, so a run can be audited and resumed.
  • W3 Scripts gate what's checkable; agents judge the rest. Five scripts can fail a stage, and a script must approve every dispatch, so loops can't run away. Page shape, checks and ToC are judged, with a stated reason.
  • W4 You approve the plan before anything expensive. A wrong premise in the plan is the costliest error, so the checkpoint is the premise check.

§ 4s-04

The idea underneath: cognitive load

example → rule → contrast · B4o-3

Just enough theory to predict whether a design choice adds or removes load for a given reader.

Opening (draft): "Read this word: characteristics. You took it in as one thing. Someone learning to read English sees fifteen letters to hold at once."

  • New information passes through a working memory that is limited in capacity and duration. What's already in long-term memory comes back as a chunk, and the limit stops applying to it. (No number is given; the research behind this page doesn't support one.)
  • Intrinsic load: how many elements of the material must be held together, relative to what you already know. Only sequencing changes it.
  • Extraneous load: effort spent on the presentation rather than the content. This is the part design controls.
  • Example: split attention. Look up "which stage writes findings.md?" in both versions of Plate III.
Why not a third, "good" kind of load?Older accounts added "germane load". Critics argued that splitting load into good, bad and neutral types lets any outcome be explained after the fact; its authors now describe it as working memory redirected to the content, not an extra quantity. So Didactician removes friction and aims attention; it doesn't add busywork.
Problem 2 · Predict · k-02
This page never explained what a subagent or a context window is. For you, would adding a step-by-step explanation of them have raised or lowered your cognitive load?
  1. A) Lowered: more explanation always makes things easier. (tempting)
  2. B) Raised: you'd spend effort checking it against what you already know.
  3. C) No effect: it's only a few paragraphs.
Solution. B. To you, "subagent" is one chunk; unpacking it costs processing and cross-checking with nothing to learn. For a reader new to agents the same paragraphs would lower load: the expertise reversal effect. That's why Didactician fixes one audience per page, and why this page moves quickly through agents and slowly through learning science.

Problem 3 · Compare · k-04
A widget lets the reader drag a slider and watch a value change. Which change does most to make it teach?
  1. A) Smoother animation and instant feedback. (tempting)
  2. B) Ask the reader to predict the result before they move the slider.
  3. C) Add two more sliders so there's more to explore.
Solution. B. Dragging is Active; predicting first is Constructive, because the reader generates something that isn't on screen, and a wrong guess followed by the result is what sticks (ICAP, framed by its authors as a hypothesis). A is good UX but doesn't change what the reader thinks about; C adds load. That's why this page asks three questions, not one per section.
